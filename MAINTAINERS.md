# Maintainers and governance

## Current maintainer

- `@zzzcws` — founding maintainer; release, security, and repository administration.

The current single-maintainer model is an acknowledged bus-factor risk. This
file will be updated as additional maintainers earn responsibility through
sustained, reviewable contributions.

## Decision process

Routine changes are decided through pull-request review. Changes to licenses,
security boundaries, destructive operations, data formats, provider adapters,
or release signing require an explicit written maintainer decision. Important
decisions should record alternatives and consequences in the pull request or an
architecture decision document.

No maintainer may commit user content, credentials, private deployment data, or
third-party material without documented redistribution rights.

## Releases

A release requires passing CI, a clean and reproducible source build, reviewed
dependency notices and SBOMs, inclusion of the Apache-2.0 project license, a
changelog entry, and a signed tag.

## Becoming a maintainer

Candidates should demonstrate sustained technical contributions, reliable
review, respect for the project's safety boundaries, and constructive community
participation. Existing maintainers approve additions and record them here.
